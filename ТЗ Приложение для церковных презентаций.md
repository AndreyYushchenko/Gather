# Gather — ТЗ на приложение для церковных презентаций

2026-09-18 · @Someone

## 1. Назначение и цели проекта

Приложение для показа контента во время церковных служб на проекторе: тексты песен, стихи из Библии, объявления и фото выводятся на экран для собравшихся.

- Работает как полноценное приложение на ПК (запускается локально, без обязательного интернета после первого запуска).
- Один человек управляет показом с одного экрана, изображение выводится на второй (проектор).
- Весь контент хранится и накапливается внутри приложения — пользователь сам наполняет базу.

Важно: это полноценное настольное приложение, а не веб-сайт и не обёртка вокруг браузера — со своим окном, иконкой и установкой, как например Steam или торрент-клиент. Пользователь не должен видеть или ощущать браузер.

Технологический стек зафиксирован: C# + .NET 8; интерфейс на WinUI 3 с компонентами CommunityToolkit.WinUI; локальная база данных SQLite с доступом через Dapper; локальный веб-адрес для вывода на OBS (/display) через ASP.NET Core Minimal API; мгновенное обновление содержимого — WebSocket/SignalR; управление окнами, вторым монитором и системными функциями — Windows App SDK; шрифт — Segoe UI Variable или Inter; иконки — Fluent Icons / Segoe Fluent Icons.

## 2. Целевая платформа и пользователи

| Параметр | Значение |
| --- | --- |
| Платформа | ПК (Windows), локальное приложение |
| Основной пользователь | оператор показа (1 человек за пультом управления) |
| Зритель | собрание, видит только окно показа на проекторе/втором экране |
| Подключение к интернету | не обязательно после установки |

## 3. Функциональные требования

### 3.1 Категории контента

| Категория | Что хранит | Особенности |
| --- | --- | --- |
| Песни | название, текст по куплетам/припеву | текст делится на слайды пустой строкой, показывается по одному куплету |
| Стихи из Библии | книга, глава:стих, текст | можно ввести вручную или вставить готовый текст перевода |
| Объявления | заголовок, текст, срок актуальности | видны только пока не удалены/не просрочены |
| Фото | изображение, подпись (опц.) | показывается на весь экран |

### 3.2 Управление контентом

- Добавление, редактирование, удаление записей в любой категории.
- Поиск по названию и тексту с фильтром по категории.
- Сортировка списка (по дате добавления, по алфавиту).
- Группировка песен и объявлений в плейлисты/подборки под конкретную службу (опционально, см. п.9).

### 3.3 Подготовка к показу

- Предпросмотр записи перед выводом на экран.
- Для песен и стихов — деление на слайды, переход вперёд/назад по слайдам.

## 4. Режим показа (окно для проектора)

- Отдельное окно на весь экран (полноэкранный режим), выводится на второй монитор/проектор.
- Крупный, хорошо читаемый шрифт; тёмный фон по умолчанию.
- Кнопка/горячая клавиша «чёрный экран» — мгновенно гасит вывод, не сбрасывая текущий слайд.
- Управление со стороны оператора: клавиатура (стрелки вперёд/назад) и кнопки в панели управления.
- Изменения в панели управления сразу отражаются в окне показа.

### 4.1 Вывод на OBS (второй ноутбук в сети)

- Приложение поднимает локальный веб-адрес в домашней/локальной сети (например, http://192.168.x.x:PORT/display).
- На втором ноутбуке в OBS добавляется источник «Браузер» (Browser Source) с этим адресом — и слайды показа появляются как источник в сцене OBS.
- Обновление слайда на панели управления мгновенно обновляет и окно на проекторе, и картинку в OBS — один и тот же источник данных.
- Требование: оба устройства должны быть в одной локальной сети (Wi-Fi/LAN); интернет не нужен.

## 5. Хранение данных

- Локальная база на самом ПК — база сохраняется между запусками, интернет не требуется.
- Фото хранятся вместе с остальными данными приложения.
- Резервное копирование: экспорт/импорт всей базы в файл (для переноса на другой ПК или бэкапа).

## 6. Интерфейс и UX

- Панель управления: слева — список/библиотека с поиском и категориями, справа — предпросмотр выбранной записи и слайдов.
- Одна кнопка «На экран» отправляет выбранный слайд в окно показа.
- Форма добавления/редактирования — минимум полей, текст песен и стихов вводится как обычный текст (разбиение на слайды автоматическое, по пустой строке).
- Загрузка фото — перетаскиванием файла или через выбор с диска.

## 7. Нефункциональные требования

- Быстрый старт: приложение готово к работе за несколько секунд.
- Стабильность во время службы — сбой окна показа не должен прерывать работу приложения.
- Библиотека выдерживает сотни записей без заметных задержек в поиске.
- Простое обновление содержимого без переустановки приложения.

## 8. Ограничения и вопросы по авторскому праву

- Приложение — это пустая база с инструментами ввода: готовые тексты песен и переводов Библии в него не встраиваются заранее.
- Тексты песен пользователь вводит сам (из своих сборников/нотных изданий); за соблюдение авторских прав на конкретные тексты отвечает пользователь.
- Для стихов из Библии стоит использовать тексты в открытом доступе (многие переводы свободны для церковного использования) — пользователь сам выбирает перевод и вводит/вставляет текст.
- Фото — личные фото пользователя или объявления, сделанные им самим.

## 9. Этапы разработки

1. Базовая логика: библиотека, категории, добавление/редактирование/удаление, локальное хранение.
2. Режим показа: окно на второй экран, слайды, переход вперёд/назад, чёрный экран.
3. Интерфейс и удобство: поиск, предпросмотр, оформление.
4. Дополнительно (по необходимости): плейлисты под службу, экспорт/импорт базы.
