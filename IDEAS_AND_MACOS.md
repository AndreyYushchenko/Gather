# Идеи по развитию проекта и портированию на macOS

Так как проект написан на **C++ и Qt6**, у вас уже есть огромное преимущество: **Qt изначально кроссплатформенный**. В отличие от связки C# + WinUI 3 (которая работает только под Windows), ваш текущий код можно скомпилировать под macOS с минимальными изменениями.

Ниже собраны идеи по адаптации для macOS и общему улучшению функционала.

---

## 🍎 1. Портирование на macOS

Поскольку используется Qt, логика и интерфейс будут работать "из коробки", но нужно учесть особенности экосистемы Apple:

### 1.1. Сборка и Архитектура
* **Apple Silicon (M1/M2/M3) и Intel:** Необходимо собирать Universal Binary (или хотя бы под ARM64), чтобы на современных макбуках приложение работало без эмулятора Rosetta 2 (для максимальной скорости и энергоэффективности).
* **Bundle (.app):** В macOS приложения собираются в специальные папки-бандлы (Sermon.app). В `CMakeLists.txt` нужно будет добавить свойства для упаковки в бандл (`set_target_properties(Sermon PROPERTIES MACOSX_BUNDLE TRUE)`).
* **Иконка приложения:** Потребуется конвертировать `app-256.png` в формат `.icns` для macOS и прописать его в `Info.plist`.

### 1.2. Особенности интерфейса macOS
* **Global Menu Bar:** В macOS главное меню находится сверху экрана, а не в окне. Qt умеет переносить `QMenuBar` туда автоматически, но нужно проверить, чтобы шорткаты вроде `Cmd+Q` или `Cmd+C` работали корректно.
* **Retina экраны:** Макбуки имеют экраны с высокой плотностью пикселей (High DPI). Qt6 отлично с этим справляется, но нужно убедиться, что все иконки (ваши SVG) рендерятся четко и картинки фонов не "мылятся".
* **Разрешения (Permissions):** macOS очень строго относится к приватности. Приложению потребуется запросить права на доступ к папке Documents/Pictures (если база хранится там) и к микрофону/камере (если будет захват видео).

### 1.3. Дистрибуция
* **DMG образ:** Для удобной установки пользователями нужно будет настроить упаковку собранного `.app` в файл `.dmg` (например, с помощью утилиты `macdeployqt`).
* **Code Signing и Notarization:** Чтобы macOS не блокировала запуск со словами "приложение от неизвестного разработчика", понадобится Apple Developer Account ($99/год) для подписи кода и нотаризации.

## 🚀 2. Идеи по новому функционалу (Общие для всех ОС)

### 2.1. Режим суфлера (Stage Display)
* Вывод отдельного окна для проектора в зале (красивый фон, текст) и отдельного окна для музыкантов/пастора на сцене (черный фон, белый текст, аккорды, таймер, часы, следующая строка).

### 2.2. Интеграции и Контент
* **Библия через API:** Добавить возможность скачивания популярных переводов Библии (Синодальный, НРП) через открытые API или форматы (Zefania XML), чтобы не вводить стихи вручную.
* **SongSelect / CCLI:** Если у церкви есть лицензия, сделать прямой импорт христианских песен с аккордами.

### 2.3. Улучшение показа
* **Плавные переходы (Fade In / Fade Out):** Мягкая смена слайдов вместо резкого переключения.
* **Слои:** Возможность выводить текст поверх видео-фона (mp4), а поверх текста — таймер или срочное объявление, не прерывая фон.
* **Поддержка NDI:** Передача видео по локальной сети в OBS в высоком качестве с прозрачностью (вместо или в дополнение к веб-серверу).

### 2.4. Управление и UX
* **Веб-пульт с телефона:** Простая веб-страница, которую раздает само приложение. Позволяет оператору или пастору переключать слайды со смартфона по Wi-Fi.
* **Умный поиск:** Поиск песен не только по названию, но и по кускам текста из припева с учетом опечаток.
* **Облачная синхронизация:** Синхронизация базы `sqlite` через Google Drive или iCloud, чтобы несколько операторов всегда имели актуальную базу.
* **Глобальные горячие клавиши:** Управление презентацией (вперед/назад, черный экран) даже если окно приложения свернуто.
